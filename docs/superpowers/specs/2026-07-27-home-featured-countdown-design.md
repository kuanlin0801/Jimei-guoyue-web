# 首頁「重要活動倒數」卡 — 設計文件（Design Spec）

- **日期**：2026-07-27
- **狀態**：設計定稿，待進入實作
- **關聯**：延伸 `2026-06-25-home-upcoming-events-design.md`（首頁「近期行程」清單），共用同一份 Google Calendar API 資料。

---

## 1. 背景與目標

首頁右欄「近期行程」依時間先後顯示未來 5 筆，例行課與大型活動一律平等對待。實際情況是：暑訓期間例行課密集，8/22 的「新生體驗招生活動」被前面一整排胡琴／提琴課擠出前 5 筆，家長在首頁完全看不到它。

**目標**：讓家長一進站就看到「下一個重要活動還有幾天」，產生時間感與準備意識。

**關鍵限制**：不能用「取最近一筆」自動判定——第一筆通常是例行課。必須有一個**幹部零程式、零新工具**的方式標記「這筆重要」。

---

## 2. 核心設計決策

| 項目 | 結論 | 說明 |
|---|---|---|
| 重要活動判定 | **既有日曆的活動標題加 `★`** | 幹部改標題即可；不新增日曆、不新增試算表；活動時間永遠與日曆同一份資料 |
| 相容標記 | `★`、`⭐`、`【重要】` 皆認得 | 程式寬鬆接受，文件只教 `★`，避免幹部記錯就失效 |
| 為何不用 `【重要】` 當主標記 | 行事曆頁是 Google 月曆嵌入，每格很窄 | `【重要】新生體驗招生活動` 會被截成「【重要】新生體…」反而蓋掉真正的活動名稱；`★` 只吃一字元 |
| 顯示筆數 | **最近一筆做大卡＋其餘最多 2 筆小字列**（合計上限 3） | 大卡負責時間感；同時有多件大事時不遺漏，且右欄不會被撐長 |
| 卡片內容 | **天數＋活動名稱＋日期（星期）** | 刻意不放時間、地點、描述——先求精簡，之後要加再說 |
| 標記字元處理 | **顯示前一律移除** | 卡片與「近期行程」皆顯示乾淨標題；`★` 只存在於 Google 端與行事曆嵌入畫面 |
| 位置（桌機） | 右欄最上方，「近期行程」整組往下移 | |
| 位置（手機） | **提到最前面**（公告之上） | 若照桌機順序，會落在 4 則公告之後、要滑很久才看到，失去「一眼有時間感」的意義 |
| 強調色 | 朱印紅 `--seal` | 與「近期行程」的金色系區隔，一眼看出這則不一樣 |
| 資料取得 | **沿用同一次 fetch** | 不新增請求；只把每個日曆的 `maxResults` 由 10 提高到 50 |

## 3. 架構與檔案

| 檔案 | 類型 | 職責 |
|---|---|---|
| `src/lib/events.js` | 改 | 新增標記判定／移除、重要活動挑選、倒數天數與文案的純函式；`normalize` 增加 `featured` 欄位；`fetchUpcoming` 改回傳完整排序清單 |
| `src/lib/events.test.js` | 改 | 補上新純函式的 vitest 測試 |
| `src/data/sample-events.js` | 改 | 補一筆帶 `★` 的範例活動，讓本機無金鑰時也看得到卡片 |

> **隔離原則**（沿用既有慣例）：`events.js` 不碰 DOM、不讀 `new Date()`，`now` 由呼叫端注入，純函式才可測。fetch 與 `esc()` 組 HTML 留在 `index.astro` 的 client script。

**不動**：公告區、行事曆頁、Google 端任何設定、`calendars.js`。

## 4. 資料流

```
client 端（瀏覽器，頁面載入時）
  for cal of calendars:
    GET .../calendars/{id}/events?key&timeMin&singleEvents=true&orderBy=startTime&maxResults=50
    → normalize(item, cal)：title 去除標記、featured = 標題原本是否含標記
  合併四批 → toUpcoming(events, now)   ← 單一排序清單
      ├─ takeNext(all, 5)        → 「近期行程」5 列（現行行為不變）
      └─ pickFeatured(all, 3)    → 倒數卡（第 1 筆大卡、第 2–3 筆小字列）
```

`fetchUpcoming` 目前簽章帶 `count` 並只回前 5 筆；改為回傳**完整**排序清單，取數交給呼叫端。這樣一次請求同時服務兩個區塊，不必為了倒數卡多打一輪 API。

## 5. 純函式契約（給 TDD）

```js
// 標記
FEATURED_MARKERS = ['★', '⭐', '【重要】']
isFeatured(title)  -> boolean   // 標題含任一標記（位置不限，容忍幹部打在字尾）
stripMarker(title) -> string    // 移除所有標記與殘留的前後空白；無標記則原樣回傳

// 挑選（events 須為 toUpcoming 排序後的結果）
pickFeatured(events, limit = 3) -> Event[]   // 依時間序取前 limit 筆 featured，並依標題去重（見下）

// 倒數（台北日界線）
daysUntil(at, now)   -> number   // 整數天：今天 0、明天 1、8/22 對 7/27 為 26
formatCountdown(days)-> string   // 0 → '就是今天'；1 → '明天'；n → `還有 ${n} 天`
```

`normalize(item, calMeta)` 的回傳增加一個欄位：

```js
{ title, at, isAllDay, color, calName, featured }
//  ↑ 已去除標記                        ↑ 新增
```

**天數為何要用台北日界線**：若直接以毫秒差除以 86400000，「明天早上 8 點」在今天下午看會算成 0 天、在今天凌晨看會算成 1 天，同一場活動因為現在幾點而顯示不同。改用「台北當日 00:00」相減，明天永遠是明天。`events.js` 內部已有 `startOfTaipeiDay`／`taipeiYMD`，直接重用即可（`startOfTaipeiDay` 需要 export 或由 `daysUntil` 內部呼叫）。

**測試重點**：
- `isFeatured` / `stripMarker`：三種標記、標記在字首／字尾、標記後有無空白、完全無標記、空字串
- `pickFeatured`：清單中無 featured（回空陣列）、只有 1 筆、超過 limit 只取前 3、順序與時間序一致、**同標題多場次只留最早一筆**
- `daysUntil`：今天（0）、明天（1）、跨月（7/27 → 8/22 為 26）、跨年、全天活動、當天稍晚的計時活動
- `formatCountdown`：0／1／多天三種分支

## 6. 顯示規格

> **本節於 K260727H 依實作後的實物檢視修訂**。原設計是「卡內小字 eyebrow ＋ 直式堆疊、天數 30px」，做出來後判定兩點不成立：①右欄變成「無標題卡片疊在有標題卡片上」，與左欄不一致；②30px 的天數撐不起「時間感」這個唯一目的。下方為實際上線的版本，原設計保留於本段末尾備查。

```
● 重要活動                        ← sec-head，朱紅圓點，與「最新公告」「近期行程」同一套
┌──────────────────────────────┐
│ 新生體驗招生活動        還有    │
│ 8/22（週六）           26 天   │  ← 左：名稱＋日期／右：62px 數字
│ ──────────────────────────── │
│ 9/13  校慶音樂會        48 天  │  ← 第 2 筆（有才顯示）
│ 10/5  全國賽            70 天  │  ← 第 3 筆（有才顯示）
└──────────────────────────────┘
● 近期行程
┌──────────────────────────────┐
│ （現有卡片，內容與行為不變）     │
└──────────────────────────────┘
```

- **區段標題**：`<h2 class="sec-head first">` ＋ `sec-dot seal`，固定文字「重要活動」。放在 `#home-featured` 內部，故沒有 `★` 活動時連標題一起隱藏。
- **主區塊**：左 `.feat-main`（名稱 17px ＋ 日期 13px）／右 `.feat-count`（`還有` 12px 疊在上、數字 62px、`天` 19px）。左右結構刻意與下方小字列一致，整張卡是同一套「左內容／右天數」邏輯。
- **無數字的兩種狀態**：`明天`／`就是今天` 沒有數字可拆，右欄容不下同級大字，改回**整排 40px 大字詞**（`.feat-head-word`）。兩種版型一次只會出現一種。
- **小字列**：沿用「近期行程」列的三欄骨架（左日期／中標題／右天數）；只顯示天數不顯示星期，與主區塊拉開層級
- **分隔線**：`--line-soft`，僅在有第 2 筆時出現
- **無 `★` 活動**：整個 section 不出現（`hidden`），版面完全回到現行樣子
- **寬度實測**（371px 桌機欄寬／327px 手機）：標題可用寬 214／171px；13 字標題桌機一行、手機兩行；18 字＋三位數天數桌機兩行、手機三行，皆不溢出

### 版面實作
`.home-cols` 由兩個 grid item 變三個，改用具名區域以便手機重排：

```css
.home-cols{grid-template-columns:1.6fr 1fr;grid-template-rows:min-content 1fr;grid-template-areas:"ann feat" "ann up"}
@media(max-width:720px){
  .home-cols{grid-template-columns:1fr;grid-template-rows:auto;grid-template-areas:"feat" "ann" "up"}
}
```

⚠️ **`grid-template-rows:min-content 1fr` 不可省略**（K260727H 補上）。左欄 `ann` 跨兩列，若兩列都是 `auto`，左欄多出來的高度會依 CSS Grid §12.5 分配進倒數卡那一列，把「近期行程」往下推——實測公告長時推 837px，且**沒有 `★` 活動、卡片 `display:none` 時整個右欄掉到頁面最底**（正是「無重要活動時版面不變」這條保證要防的情況）。第二列用 `1fr` 這種彈性尺寸即可把跨列項目排除在內在尺寸分配之外。日後改動此區 grid，務必用「左欄很長 × 卡片顯示／隱藏」四種組合驗證。

倒數卡由 client script 注入 `#home-featured-card`，樣式需放 `<style is:global>`（與現行 `.ev-row` 等相同理由）；區段標題是 Astro 模板的靜態內容，樣式走既有的 `.sec-head`。

## 7. 降級與錯誤處理

| 情況 | 行為 |
|---|---|
| 沒有任何 `★` 活動 | 倒數卡不顯示；「近期行程」照常 |
| 重要活動排在抓取範圍之外 | 同上——不顯示、不破版（見下方風險） |
| 金鑰未設 | 走 `sample-events.js`；範例資料含一筆 `★` 活動，卡片照常顯示 |
| fetch 失敗 | 倒數卡不顯示；「近期行程」維持現行的「行程載入失敗」一行 |
| 標題含 HTML／超長 | 一律 `esc()` 跳脫後才組 `innerHTML`；標題以 CSS 截斷，不破版 |

**已知風險（可接受）**：每個日曆抓未來 50 筆。暑訓期間課表密集時，50 筆約涵蓋未來兩個月；若重要活動排在更遠的未來，倒數卡不會出現。實務上重要活動很少在兩個月前就進日曆，且失效模式是「安靜地不顯示」而非破版。若日後發現不夠，調高 `maxResults` 即可（回應仍是單次請求，成本低）。

**不放 skeleton**：倒數卡預設 `hidden`，資料到才顯示。若改放 skeleton 佔位，最終沒有重要活動時會出現「先閃一張卡再消失」，比單純的內容推移更擾人。

## 8. 安全

- 活動標題來自 Google 日曆（幹部可寫入），組 HTML 前一律 `esc()` 跳脫，與公告／近期行程同一套做法。
- 本設計不新增任何外部資料來源、不新增環境變數、不改動 API 金鑰的限制設定。

## 9. 幹部維運（一次性教學，非程式）

1. 在任一樂團日曆建立活動時，**標題最前面加一個 `★`**，例如 `★新生體驗招生活動`。
2. 不需要另外通知網站或做任何設定，重新整理首頁就會看到倒數（讀的是 Google 日曆即時資料，沒有公告試算表那種 5 分鐘快取）。
3. 活動當天過後**自動消失**，不必回頭清理；若同時有多個 `★` 活動，網站取時間最近的 3 個。
4. 想取消強調，把標題的 `★` 刪掉即可。

### 四個容易踩到的行為（要口頭交代，網站無法代勞）

| 情況 | 實際行為 | 建議做法 |
|---|---|---|
| `★` 標在**週期性活動**上 | 日曆讀取用 `singleEvents=true`，週期性活動會展開成「每一次各一筆」、標題全相同。`pickFeatured` 已依標題去重、只留最近一場（K260727G），否則三個欄位會被同一個活動的連續日期佔滿 | 可以標，但只會顯示最近一次 |
| **跨多天的全天活動**（如 8/20–8/25 暑訓） | `isUpcoming` 只看**開始日**，進入第二天後這筆就被判定為過去而從倒數卡消失——即使活動還在進行 | 想倒數就**標在第一天**，或另建一筆單日活動來標 |
| **有指定時間的活動**（如 14:00 音樂會） | 一過開始時間就從卡片消失、換下一場。所以「就是今天」實務上只在活動開始前看得到 | 屬預期行為，知道即可 |
| 重要活動排在**很遠的未來** | 每個日曆只抓未來 50 筆，超出範圍就抓不到，症狀是**卡片安靜地不出現**（不破版、不報錯） | 太早排的活動先不標，接近時再標 |

## 10. 驗收標準

- `npm test` 綠（`events.test.js` 含新增案例）。
- `npm run build` 無誤。
- 預覽（`npm run preview` 靜態站）：桌機倒數卡在右欄最上方、「近期行程」在其下；手機（≤720px）倒數卡在公告之上。
- 範例資料（無金鑰）情境下卡片正確顯示天數、名稱、日期，且帶「（範例資料…）」標示。
- 移除範例中的 `★` 後卡片消失、版面與現行一致。
- **grid 高度不變性**（K260727H 新增，最容易漏）：把左欄公告撐到遠高於右欄（實測 1665px），量「近期行程」標題的 y——**卡片顯示與隱藏兩種狀態下都必須與左欄短時相同**。這項用範例資料驗不出來（範例只有 3 則公告、左欄 467px，剛好低於觸發門檻），必須手動灌長內容。

## 11. 不做（YAGNI）

- 不顯示活動時間、地點、描述副標、報名連結（本次只做天數＋名稱＋日期）。
- 不做「加入我的日曆」「查看詳情」等按鈕。
- 不做倒數的即時刷新（秒數跳動）；天數以載入當下計算即可。
- 不新增「重要活動」日曆、不新增試算表欄位。
- 不動公告區、行事曆頁與其餘頁面。
