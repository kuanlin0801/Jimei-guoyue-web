# 活動支援改版：站內即時報名／認領 設計

- 日期：2026-06-26
- 狀態：設計定案，待寫實作計畫
- 取代範圍：現行 `src/pages/support.astro`、`src/lib/support.js`、`src/data/support-events.js` 的「連出去填 Google 表單＋讀回覆 CSV」模型

## 1. 背景與痛點

社團活動的人力協調目前在 LINE 上進行，觀察到**兩種型態**：

1. **單純需要人手**（如早自習跑班招生）：用 LINE 接龍湊人數，幹部貼活動＋家長依序 +1。
2. **大型演出**（如新生準備日、家長日演出）：工作任務多且雜（主持人、搬樂器、攝影、場佈…），需要把工作「認領」分配出去，常另開一份工作調查表單。

現行網站的支援頁是「每個活動連出去填一份 Google 表單、網站讀回覆 CSV 顯示看板」。本次改版的目標：

- **站內直接報名／認領**：家長在網頁上填稱呼、按送出即完成，不必跳出去填表單。
- **看板真即時**：任何人開／重整頁面，數秒內看到最新報名。
- **幹部零程式自助設定活動**：新增活動＝編輯一份 Google 試算表，不必改程式、不必找開發者。
- **同一套機制涵蓋兩型**：接龍是簡單情形、分工是複雜情形，共用同一資料模型與元件。

## 2. 關鍵決策摘要

| 議題 | 決策 |
|---|---|
| 報名方式 | **站內填稱呼直接送出**（非連出去填 Google 表單） |
| 活動定義放哪 | **Google 試算表**（幹部自助），非程式碼 |
| 寫入機制 | **Google Apps Script `doPost`**（零 Cloudflare 後端／金鑰） |
| 讀取機制 | **Apps Script `doGet` 即時讀**，失敗自動退回發布 CSV |
| 資料模型 | **統一「工作清單」模型**：活動底下有 N 個工作，每工作要 k 人、可內定 |
| 兩型差異 | 純呈現差異（接龍＝名單列；分工＝工作表格），同一元件依 `類型` 切換 |
| 隱私 | 看板只顯示「稱呼」，不收不顯示電話 |

## 3. 角色與分工

| 工作 | 由誰 | 頻率 |
|---|---|---|
| 部署 Apps Script、設環境變數、重新部署 | 開發者（你） | 一次性 |
| 新增活動／調整需求人數（編輯試算表） | 幹部 | 每場活動 |
| 站內報名／認領 | 家長 | 即時 |

## 4. 架構與資料流

```
幹部（編輯試算表）              家長（手機開網站）
   │ 活動／工作／需求人數           │ 填稱呼／選工作 → 送出
   ▼                              ▼
┌──────────────────┐  doPost  ┌──────────────┐
│   Google 試算表    │◀────────│  Apps Script  │
│ 活動·工作·報名分頁 │  doGet   │  Web App      │
└─────────┬────────┘────────▶ └──────┬───────┘
   (後備)發布CSV│                 即時JSON│  ▲送出
              ▼                        ▼  │
        ┌───────────────────────────────────┐
        │  靜態網站 support.astro            │
        │  讀：doGet(即時) → 失敗退回 CSV     │
        │  寫：表單送出 → doPost              │
        └───────────────────────────────────┘
```

- **讀（看板）**：頁面載入 → 打 Apps Script `doGet`，回傳「活動／工作／報名」三組資料的 JSON（讀現場試算表、無 5 分鐘快取）→ 交給純邏輯 `src/lib/support.js` 組成看板 view model → 渲染。
- **讀的後備**：`doGet` 失敗／逾時（script 出錯或超量）→ 改抓三份「發布到網路」CSV，經 `csv.js` 解析後走**同一套** `support.js` 組裝邏輯渲染（此時退回最多約 5 分鐘延遲，但看板仍可看）。
- **寫（報名）**：表單送出 → `doPost` 帶 `活動／工作／稱呼／token` → script 驗證後 append 一列到「報名」分頁。
- **即時感**：送出者自己樂觀即時顯示；其他人靠 `doGet` 即時讀（重整／重進即最新）。另加「頁面開著每約 30 秒自動更新」（分頁隱藏時暫停，省 quota）。

設計原則：**彙整邏輯集中在可測的純函式 `support.js`**，Apps Script 維持很薄（只做「讀試算表→JSON」與「append 一列」），即時路徑與 CSV 後備路徑最終都匯流到同一套 `support.js` 組裝函式。

## 5. 試算表結構（幹部的介面，一份試算表三分頁）

### 5.1 `活動` 分頁（一列一活動）

| 名稱 | 日期 | 時間 | 類型 | 狀態 | 需求人數 | 說明 | LINE連結 |
|---|---|---|---|---|---|---|---|
| 早自習跑班招生 | 2026-06-29 | 8:00-8:40 | 接龍 | 開放 | 8 | 需搬樂器、椅子、發傳單 | （選填） |
| 8/22 新生準備日 | 2026-08-22 | 10:00-11:00 | 分工 | 開放 | （留空） | … | … |

- `類型`：`接龍` 或 `分工`。
- `狀態`：`開放`／`額滿`／`結束`。
- `需求人數`：**僅接龍用**（單一數字）；分工活動留空，人數定義在「工作」分頁。
- `名稱` 是各分頁的關聯鍵（見 5.2）。同名活動請避免（必要時加日期區分）。

### 5.2 `工作` 分頁（僅「分工」活動使用，一列一工作）

| 活動 | 工作 | 需求人數 | 指定 |
|---|---|---|---|
| 8/22 新生準備日 | 主持人 | 1 | 黃子玉 |
| 8/22 新生準備日 | 搬樂器 | 4 | （留空） |
| 8/22 新生準備日 | 攝影 | 1 | （留空） |

- `活動` 欄用**試算表「資料驗證」下拉**＝從「活動」分頁的名稱挑選，避免打錯（消除跨分頁關聯的最大風險）。
- `指定` 有填＝已內定（看板顯示該名字、不可被認領、計入已滿）；留空＝開放認領。
- 接龍活動**不在此分頁建列**（其需求人數寫在「活動」分頁）。

### 5.3 `報名` 分頁（Apps Script 自動寫入；幹部一般不手動改）

`時間戳記 | 活動 | 工作 | 稱呼`

- 接龍報名：`工作` 欄留空。
- 校正（刪除誤報）：幹部手動刪該列即可。

## 6. 兩型的看板呈現（同一元件依 `類型` 切換）

### 6.1 接龍型

一張卡：活動名稱／日期／時間／說明 ＋ 進度「已報 4／需 8（還缺 4）」＋ 編號名單（侑亭媽、彥辰媽、芳語爸、好恩爸…）＋ 一顆「＋ 我要報名」。視覺貼近 LINE 接龍。

### 6.2 分工型

一張卡：活動資訊 ＋ 工作表格，每列 `工作｜需求｜已認領者｜還缺`：

- 已內定：`主持人：黃子玉 ✓`（不可認領）。
- 開放未滿：`搬樂器：王爸、李媽（已 2／需 4）` ＋ 列尾「認領」鈕。
- 已滿：顯示「足夠 ✓」、收起認領鈕。

### 6.3 共通

- 活動依日期排序；`狀態=結束` 的活動可收進「已結束」區或隱藏（實作計畫定）。
- 無任何活動時顯示空狀態文案。

## 7. 站內報名／認領流程

1. 家長點「＋ 我要報名」（接龍）或某列「認領」（分工）。
2. 跳出極簡輸入：**只填「稱呼」**（例：侑亭媽）。分工型已帶入對應「工作」。
3. 送出 → `doPost`（`活動／工作／稱呼／token`）→ 寫入「報名」分頁。
4. **樂觀更新**：送出當下，自己畫面立刻把名字加入名單／進度 +1。
5. **確認與回填**：讀 `doPost`／後續 `doGet` 回傳，確認成功並以權威資料回填看板；送出失敗則提示重試、回復樂觀變更。
6. **狀態防呆**：`額滿`／`結束` 或該工作已滿 → 不顯示送出鈕。

## 8. Apps Script 接口與安全

- `doGet`：讀「活動／工作／報名」三分頁 → 回傳 JSON。讀取為公開資料（即發布 CSV 會公開的同一份），可開放存取。
- `doPost`：驗證必填欄位、字串長度上限、比對共用 `token`，通過才 append 一列到「報名」。
- 部署為「任何人皆可存取」以接受站內匿名請求。
- **token 定位（誠實說明）**：`token` 放在 `PUBLIC_*` 環境變數＝會被編進前端、原始碼可見，**只能擋隨機掃描／亂打，不是真正鑑權**。真要防濫用需後端或驗證碼，列為未來。對小型私密家長社群，此程度足夠。
- 前端凡「來自試算表的文字」一律 `esc()` 後再組 `innerHTML`（沿用站上防 XSS 慣例）；`LINE連結` 經 `isSafeHref` 擋 `javascript:` 等注入。
- 輪詢省量：`document.visibilitychange` 分頁隱藏時暫停輪詢；Apps Script 配額對小社群同時在線人數綽綽有餘。
- **CORS／實作風險（誠實標註）**：跨來源讀 `doGet` JSON 與 `doPost` 回應需處理 Apps Script 的 CORS／302 轉址細節（實作時以簡單請求避免 preflight）。萬一某瀏覽器讀不到回應，本設計已內建兩道安全網——讀取退回 CSV、送出採樂觀更新——故即時性退化但功能不致中斷。

## 9. 程式檔案結構與設定

### 9.1 環境變數（`PUBLIC_*`，於 Cloudflare Build 變數設定）

- `PUBLIC_SUPPORT_API_URL`：Apps Script Web App 網址（同時供 `doGet` 讀看板與 `doPost` 送出，以 `action` 參數區分）。
- `PUBLIC_SUPPORT_TOKEN`：送出用共用 token（輕量防呆）。
- 後備 CSV（選填、可後補）：`PUBLIC_SUPPORT_ACTIVITIES_CSV`、`PUBLIC_SUPPORT_JOBS_CSV`、`PUBLIC_SUPPORT_RESPONSES_CSV`。
- 未設定時：fallback 到 `public/sample-support-*.csv`，讓無真實後端也能開發。

### 9.2 檔案

- `src/lib/support.js`（純邏輯、擴充 vitest）：重構為以**資料列陣列**為輸入的組裝函式（與資料來源解耦），例如 `buildSupportView({ activities, jobs, responses })` → 回傳每活動 view model（類型、狀態、各工作 `target/signed/short/enough/claimers/assigned`、接龍名單）。即時 JSON 與 CSV 後備都先轉成同形陣列再餵入。移除舊的「能否到場／不可」出席排除邏輯（新模型送出＝報名，無此情況）。
- `src/lib/csv.js`：沿用 `parseCsvRows`／`isSafeHref`（後備路徑解析用）。
- `src/pages/support.astro`：依 view model 渲染兩型卡片、接好送出表單與輪詢；保留載入中／失敗／空狀態。
- `src/data/support-events.js`：**移除**（活動定義改由試算表）。
- `public/sample-support-activities.csv`／`sample-support-jobs.csv`／`sample-support-responses.csv`：開發範例（取代現有 `sample-support-responses.csv`）。
- Apps Script 原始碼：放 repo 當參考（如 `docs/superpowers/` 旁或 `apps-script/support.gs`），手動部署，不進 Astro build。

### 9.3 測試（vitest，只測 `src/lib`）

`buildSupportView` 的純邏輯涵蓋：

- 接龍：單一隱含工作，名單與進度（已報/需求/還缺）正確。
- 分工：多工作，`指定` 計入已滿且標示內定、開放工作的 signed/short 正確。
- 邊界：需求人數為 0／留空、報名數超過需求（顯示足夠、short 不為負）、`額滿`／`結束` 狀態旗標、空資料。
- 安全：欄位文字交給呈現層 `esc()`（純邏輯不組 HTML）。

## 10. 隱私與邊界情況

- **隱私**：看板僅顯示「稱呼」；不收電話。私下聯絡走 LINE。
- **額滿／結束**：收掉送出鈕、顯示狀態字樣（名單仍可看）。
- **重複報名**：小社群允許；可於送出前輕量提示「你已在名單上？」；幹部可刪列校正。
- **誤報取消**：v1 由幹部在「報名」分頁刪列（自助取消需身分比對，列為未來）。
- **讀取失敗**：`doGet` 失敗 → 退回 CSV；CSV 也失敗 → 顯示「看板載入失敗，請稍後再試」。
- **送出失敗**：提示重試、回復樂觀變更。

## 11. 上線待辦（之後另出操作檢查表）

- **你（一次性）**：
  1. 建一份 Google 試算表，含「活動／工作／報名」三分頁，並於「工作」分頁的 `活動` 欄設資料驗證下拉。
  2. 貼上 Apps Script、部署為 Web App（任何人可存取），記下網址。
  3. （選填）將三分頁「發布到網路」成 CSV，當即時讀取的後備。
  4. 設定環境變數（`PUBLIC_SUPPORT_API_URL`、`PUBLIC_SUPPORT_TOKEN`、選填三組後備 CSV），重新部署。
- **幹部（日常）**：在試算表新增活動列／調整需求人數即可。

## 12. 範圍與不做（YAGNI）

- **不做**：學生獨奏曲目名單（屬演出內容／公告，不進支援看板）、可支援時段細分、家長自助取消、伺服器端強鑑權、WebSocket 推播。
- **聚焦**：兩型人力的「幹部設定 → 站內報名／認領 → 即時看板」這條主線。
